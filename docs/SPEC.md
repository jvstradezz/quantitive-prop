# SPEC — Quantitive Prop

Статус: черновик M0 · 2026-10-28 · владелец: Nikita

Связанные документы: [ARCHITECTURE](ARCHITECTURE.md) · [VALIDATION](VALIDATION.md) · [MONTE_CARLO](MONTE_CARLO.md) · [IDEAS](IDEAS.md) · [DESIGN](DESIGN.md) · [ROADMAP](ROADMAP.md) · [DECISIONS](DECISIONS.md)

## 1. Цель

Автоматический конвейер для CFD-пропов: генерирует стратегии на всех рынках фирм (форекс, металлы, индексы, сырьё), отбраковывает слабые и переобученные, через Monte Carlo считает вероятность пройти проп каждого типа, подбирает лучший тип пропа и риск по фазам. Лучшие стратегии идут в демо-форвард автоматически, на проп-аккаунты — только с ОК Nikita.

**Метрика успеха** — `P(1-я выплата)` на живых данных (демо-форвард, затем проп). Не «% в месяц» в бэктесте.

Доходность не ограничиваем. Высокая цифра — не причина отказа, а повод проверить её теми же гейтами ([VALIDATION](VALIDATION.md)).

## 2. Границы

**Входит:**
- Данные: тиковые bid/ask Dukascopy (бесплатно), калибровка по выгрузке и спецификациям платформы фирмы (MT5).
- Движок бэктеста с издержками, внутридневной эквити, MAE/MFE.
- Проп-симулятор Monte Carlo для всех типов пропов ([MONTE_CARLO](MONTE_CARLO.md)).
- Гейты S0–S6, робастность, автоотказ.
- Окно идей Nikita (чат и страница «Идеи») и автопоиск по семействам стратегий.
- Демо-форвард-раннер, адаптер исполнения MT5, предохранители, Telegram-уведомления.
- Дашборд: Идеи, Leaderboard, Стратегия, Prop simulator, Bots.

**Не входит:**
- Ручная стратегия Nikita по NAS100: не автоматизируем, не предлагаем, не анализируем.
- Платные данные и подписки без ОК.
- Мартингейл, сетка, усреднение против позиции, сделки без стопа, HFT, тик-скальпинг, латентный арбитраж, хедж между счетами, EA «для прохождения челленджей», копирование на funded — автоотказ (см. [VALIDATION §6](VALIDATION.md#6-автоотказ)).

| Проскальзывание | | | |
| Доля издержек от валовой | | | |

## 7. Предохранители бота (не отключаются)

| Предохранитель | Значение |
|---|---|
| Внутренний дневной стоп | 50% дневного лимита фирмы (максимум 70%), закрыть всё и не торговать до сброса дня |
| Внутренний общий стоп | 60% общего лимита фирмы, закрыть всё и остановить бота до решения Nikita |
| Стоп у брокера | у каждой позиции; объём от стопа и риска фазы |
| Лимиты | сделок в день, фильтр новостей и выходных, окно 00:00–02:00 сервера |
| Контроль | kill switch, heartbeat, Telegram (из процесса-монитора), полный лог |
| Parity | бэктест vs живое исполнение ≥ 99% совпадения сделок |
| Пауза | живая просадка за 99-м перцентилем MC |

Изменение — только с ОК Nikita и записью в [DECISIONS](DECISIONS.md).

## 8. Нефункциональные требования

- **Детерминизм.** Каждый запуск MC и бэктеста воспроизводим: фиксированный seed, хэш данных, коммит, хэш конфига в `manifest.json` отчёта.
- **Без доступа к будущему.** Проверка тестами на каждом PR.
- **CI < 3 мин**, без сети, на маленьких фикстурах. Тяжёлые прогоны — локально или ночью, результаты в `reports/`.
- **Качество.** `make check` = ruff + mypy + pytest (+ hypothesis) зелёный перед «готово».
- **Время.** Хранение в UTC. Отображение: ET и МСК, время сервера брокера — явно.
- **Консерватизм.** Где данные расходятся или неизвестны — берём худший вариант и пишем допущение.
- **Производительность (цель, уточняется в M1).** 10 000 путей × 3 фазы × до 250 торговых дней — < 5 с на одном ядре (numba). Оптимизатор риска на одну пару стратегия × программа — < 2 мин.

## 9. Глоссарий

| Термин | Значение |
|---|---|
| R | Результат сделки в единицах начального риска: −1R = убыток по стопу без издержек |
| MAE / MFE | Max Adverse / Favorable Excursion — худший и лучший плавающий результат сделки |
| IS / OOS | In-sample (подбор) / out-of-sample (проверка на невиденных данных) |
| WF, WFE | Walk-forward — скользящая переоптимизация; WFE — отношение доходности OOS к IS |
| DSR | Deflated Sharpe Ratio — Sharpe с поправкой на число перепробованных вариантов |
| PBO | Probability of Backtest Overfitting — вероятность, что лучший на IS вариант хуже медианы на OOS |
| EOD-трейлинг | Общий лимит, который подтягивается за максимумом баланса на конец дня |
| EV на взнос | Ожидаемый денежный результат одной покупки челленджа с учётом взноса и выплат |
| B0 | Начальный баланс аккаунта |
| Сервер | Время торгового сервера фирмы; FN — GMT+2 зимой / GMT+3 летом |
