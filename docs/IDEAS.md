# IDEAS — окно идей

Статус: черновик M0 · 2026-10-28

Идеи Nikita проходят тот же конвейер, что и автопоиск ([VALIDATION](VALIDATION.md)): карточка → код → S1–S3 → вердикт. До M2 (нет движка) идея получает только карточку и место в очереди.

## 1. Поток

```
Чат: «Идея: …»  ─────────┐                                  ┌─► ответ в чат
(текст, голос, скрины,   │                                  │
 ссылки, видео)          ▼                                  │
                  Формализация ──► тред [sonnet, xhigh] ──► отчёт ──► вердикт
                  (карточка,       код, S1–S3, мутации,              │
                   ≤ 3 вопроса)    счётчик вариантов                 ├─► Демо (S4 автоматически)
                         ▲                                           ├─► Отклонена (почему)
Дашборд «Идеи» ─► GitHub │                                           └─► доработать (что) ─► Кодится
  POST /api/ideas   Issue [idea] ─► scheduled task (GitHub-триггер) ─┘   + комментарий в issue
```

### 1.1 Из чата

1. Nikita пишет «Идея: …». Координатор запускает обработку сразу, без «ок» (инструкции §3).
2. **Формализация**: карточка `research/registry/IDEA-NNNN-<slug>.yaml` (§3). Неясно критичное — до 3 вопросов одним сообщением; мелочи — решаем сами и пишем в `assumptions`.
3. **Тред [sonnet, xhigh]**: кодит стратегию, гонит S1–S3 по всем подходящим инструментам фирм и вариантам выходов — RR 1:1 / 1:2 / 1:3, трейлинг, частичные, безубыток, выход по времени. Затем 5–20 мутаций. **Все** варианты — в счётчик для DSR.
4. **Ответ** (§4): лучшие варианты, издержки, таблица пропов, вердикт одной строкой.

### 1.2 Со страницы «Идеи» (M5)

1. Поле ввода как чат → `POST /api/ideas` → API создаёт GitHub Issue с меткой `idea`: заголовок `Идея: <первая строка>`, тело — текст и ссылки на вложения.
2. Scheduled task проекта с GitHub-триггером на метку `idea` запускает обработку — те же шаги, что в 1.1.
3. Вопросы и результат — комментариями в issue; карточка и реестр обновляются PR.
4. Статус в issue — метками: `status:formalized`, `status:coding`, `status:testing`, `status:result`, `status:demo`, `status:rejected`.
5. Кнопка «доработать» на карточке → `POST /api/ideas/{id}/rework` с текстом → комментарий в issue + метка `rework` → триггер.

Для API нужен GitHub-токен с правом `issues:write` на этот репозиторий — запросим у Nikita в M5.

### 1.3 До M2

Только карточка со статусом `Новая` или `Формализована` и место в очереди (§5). Код и тесты — после готовности движка.

## 2. Статусы

| Статус | Значит | Кто переводит |
|---|---|---|
| Новая | идея записана, карточка не заполнена | координатор |
| Формализована | карточка заполнена, вопросы закрыты | координатор |
| Кодится | тред пишет стратегию | тред |
| Тест | идут S1–S3 и мутации | тред |
| Результат | отчёт готов, вердикт вынесен | тред |
| Демо | прошла S3, идёт демо-форвард (S4) | авто |
| Отклонена | провалила гейт или автоотказ; причина в карточке | тред |

«Доработать» — не статус, а действие: возвращает в `Кодится` с записью в `history`.

## 3. Карточка идеи

Файл `research/registry/IDEA-NNNN-<slug>.yaml`, схема `IdeaCard` (pydantic, T2). Время сессий — в ET, МСК и времени сервера фирмы.

```yaml
id: IDEA-0001
title: "Range bot по мотивам Sniper Range Bot V2"
status: Новая                 # Новая | Формализована | Кодится | Тест | Результат | Демо | Отклонена
created: 2026-10-28
author: Nikita
source:
  channel: chat               # chat | dashboard | generator
  ref: null                   # ссылка на сообщение или GitHub Issue
  attachments: []
summary: >
  Одна-две фразы: что торгуем и почему это может работать.
markets:
  asset_classes: [index_cfd]
  instruments: [NAS100, US30, SPX500, GER40]   # все подходящие у фирм
timeframes: [M1, M5]
sessions:                     # ET → МСК (летнее время США / зимнее) → сервер FN
  - {name: ny_open_30, et: "09:30-10:00", msk: "16:30-17:00 / 17:30-18:00", server_fn: "16:30-17:00"}
entry: "..."
stop: "..."
take: "..."
exits: [rr_1_1, rr_1_2, rr_1_3, trailing, partial, breakeven, time_exit]
filters: []
firm_rules: [settlement_window, news_filter, min_hold_120s, max_trades_day]
assumptions: []               # всё, что решили сами
questions: []                 # ≤ 3, только критичное
variants_tested: 0            # счётчик для DSR (дублируется в variants.parquet)
holdout_opened_at: null
results: []                   # ссылки на reports/<run_id>/
verdict: null                 # "в демо" | "доработать: …" | "отклонена: …"
history:
  - {date: 2026-10-28, status: Новая, note: "записана из чата"}
```

## 4. Ответ по идее

Сводка до 30 строк, детали — в `reports/<run_id>/`.

1. **Лучшие варианты** (до 5): инструмент, ТФ, сессия, выходы, сделок, PF, `mean R`, гейты S1–S3 (✓ / ✗).
2. **Издержки** лучшего варианта — таблица из [SPEC §6](SPEC.md#6-отчёт-по-стратегии-обязательный-формат): валовая, спред, комиссия, своп, проскальзывание (каждое в $, % и R), доля издержек, чистый результат.
3. **Таблица пропов** — [MONTE_CARLO §9](MONTE_CARLO.md#9-выход).
4. **Вердикт** одной строкой: `в демо` / `доработать (что)` / `отклонена (почему)`.
5. Сколько вариантов перепробовано (`variants_tested`) и DSR.

### Идея №1 — Range bot по мотивам Sniper Range Bot V2

Черновик карточки. Допущения — предварительные, уточняются при формализации.

```yaml
id: IDEA-0001
title: "Range bot по мотивам Sniper Range Bot V2"
status: Новая
created: 2026-10-28
author: Nikita
source:
  channel: chat
  ref: "сообщение Nikita в чате проекта, 2026-10-28"
  attachments: []
summary: >
  Чужой бот на NQ-фьючерсах; судя по названию, торгует диапазон. Стоп и тейк 1:1,
  направление по дню недели. Его отчёт: 138 сделок, винрейт 73%, Monte Carlo
  на $50K eval (цель +$3 000, EOD-трейлинг $2 000) — 93% прохождения.
markets:
  asset_classes: [index_cfd]
  instruments: [NAS100, US30, SPX500, GER40]   # NAS100 — основной, остальные — проверка «не один инструмент»
timeframes: [M1, M5]
sessions:   # ET → МСК (летнее время США / зимнее) → сервер FN (если FN = ET+7)
  - {name: asia_range,   et: "20:00-00:00", msk: "03:00-07:00 / 04:00-08:00", server_fn: "03:00-07:00"}
  - {name: london_range, et: "03:00-05:00", msk: "10:00-12:00 / 11:00-13:00", server_fn: "10:00-12:00"}
  - {name: ny_first_15,  et: "09:30-09:45", msk: "16:30-16:45 / 17:30-17:45", server_fn: "16:30-16:45"}
  - {name: ny_first_30,  et: "09:30-10:00", msk: "16:30-17:00 / 17:30-18:00", server_fn: "16:30-17:00"}
  - {name: ny_first_60,  et: "09:30-10:30", msk: "16:30-17:30 / 17:30-18:30", server_fn: "16:30-17:30"}
entry: >
  Два семейства: (а) пробой — стоп-ордер за границей диапазона + буфер;
  (б) возврат — цена выходит за границу и закрывается обратно внутри, вход в сторону диапазона.
stop: "противоположная граница диапазона (стоп = ширина диапазона)"
take: "1 × стоп (как у оригинала); варианты ниже"
exits: [rr_1_1, rr_1_2, rr_1_3, trailing, partial, breakeven, time_exit_ny_close]
filters:
  - day_of_week: {mon: long, tue: both, wed: long, thu: short, fri: both}   # гоняем с фильтром и без
firm_rules: [settlement_window, news_filter, min_hold_120s, max_trades_day]
assumptions:
  - "Границы сессий выше — стартовые, варьируются в мутациях."
  - "Не больше 1 сделки на инструмент в день (как у оригинала, вариант — 2)."
  - "Фильтр ширины диапазона относительно ATR, чтобы отсечь узкие диапазоны с дорогим спредом и короткими сделками."
  - "Новостной фильтр обязателен: открытие NY совпадает с новостями 08:30 и 10:00 ET."
  - "Данные NAS100 — индекс Dukascopy (USATECH), калибровка спреда по спеке MT5 FN, когда придёт."
questions: []
variants_tested: 0
holdout_opened_at: null
results: []
verdict: null
history:
  - {date: 2026-10-28, status: Новая, note: "в очередь; тестируем после M2"}
```

**Что проверяем:** диапазоны Азия / Лондон / первые 15, 30, 60 мин NY; пробой и возврат; выходы 1:1 / 1:2 / трейлинг (плюс стандартный набор); с фильтром дня недели и без. **Главный вопрос** — держится ли фильтр дня недели на OOS ([VALIDATION §4.5](VALIDATION.md#45-фильтры-дня-недели-и-времени-предложено)). Заявленные 93% автора — ориентир, а не цель: другой рынок (CFD, не фьючерс) и другие правила пропа.
