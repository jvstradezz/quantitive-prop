## 2. Разбиение данных

```
|<────────────── IS ~70% ──────────────>|<── holdout ~30% ──>|
|  WF: train │ test │                   |   открываем 1 раз  |
|        train │ test │                 |                    |
|              train │ test │ ...      |                    |
```

- Разбиение хронологическое, по каждому инструменту отдельно.
- **Walk-forward** внутри IS: окно обучения 24 мес, тест 6 мес, шаг 6 мес `[предложено]`. Для стратегий без параметров — те же окна, без переоптимизации.
- **Holdout** открывается один раз на версию стратегии. Факт открытия пишется в карточку (`holdout_opened_at`, коммит). Повторное открытие после изменений — это новая версия и новая запись в счётчике вариантов.
- **Вход проп-MC** = склеенные тестовые отрезки WF + holdout. MC на чистом IS — только справка.

## 3. S1 — in-sample

| Метрика | Порог | Как считаем |
|---|---|---|
| Число сделок | ≥ 200 | по всем инструментам варианта, IS |
| Profit factor | ≥ 1.3 | `PF = Σ R⁺_net / |Σ R⁻_net|` при базовых издержках |
| Матожидание при издержках × 1.5 | > 0 | `E₁.₅ = mean(R_gross − 1.5·cost_R)` |

`cost_R` = спред + комиссия + своп + проскальзывание сделки в R.

## 4. S2 — робастность

| Проверка | Порог | Метод |
|---|---|---|
| WFE | ≥ 50% | `WFE = (годовая доходность WF-test) / (годовая доходность WF-train)`, по склейке окон |
| Holdout в полосе MC | внутри 5–95% | §4.1 |
| Чувствительность | PF ≥ 1.15 при ±20% параметров | §4.2 |
| Переобучение | DSR ≥ 0.95 **или** PBO ≤ 0.2 | §4.3 |
| Стабильность по годам | см. §4.4 | `[предложено]` |
| Фильтры дня недели и времени | держатся на OOS | §4.5 `[предложено]` |
| Не один инструмент | см. §4.6 | `[предложено]` |

### 4.1 Holdout в полосе MC

1. Из сделок WF-test блочным бутстрэпом по дням строим 10 000 псевдо-историй длиной как holdout (по числу дней). Бутстрэп вложенный: каждый путь — из своей бутстрэп-копии WF-test, чтобы полоса учитывала и шум оценки по WF-test (D-034).
2. Для каждой считаем `mean R`, `max DD (R)`, win rate, PF.
3. Holdout проходит, если `mean R` не ниже 5% и `max DD` не выше 95% псевдо-историй (P-02, D-033); win rate и PF — в отчёт. Holdout **лучше** полосы — не отказ, а флаг аудита (инструкции §1).

### 4.2 Чувствительность параметров

- Каждый числовой параметр по одному: −20%, −10%, +10%, +20% (целые — минимум на шаг ±1).
- Плюс сетка 2D по двум самым чувствительным параметрам (для тепловой карты на странице стратегии).
- Проходит, если PF ≥ 1.15 **во всех** точках «по одному» на IS с базовыми издержками `[предложено: «во всех», а не «в медиане»]`.

### 4.3 DSR и PBO

**Счётчик вариантов.** Каждый прогнанный вариант (семейство × параметры × инструмент × выходы × фильтры) пишется в `research/registry/variants/<IDEA-id>.parquet` с дневной доходностью IS/WF (holdout и демо туда не попадают). N в DSR — по этому счётчику для данной идеи или семейства.

**Deflated Sharpe Ratio** (Bailey, López de Prado, 2014), на дневных доходностях при фиксированном риске:

$$
\mathrm{DSR} = \Phi\!\left(\frac{(\widehat{SR} - SR_0)\sqrt{T-1}}{\sqrt{1 - \hat\gamma_3\,\widehat{SR} + \frac{\hat\gamma_4 - 1}{4}\,\widehat{SR}^2}}\right),
\qquad
SR_0 = \sqrt{V[\widehat{SR}_n]}\left((1-\gamma)\,\Phi^{-1}\!\left(1-\tfrac{1}{N}\right) + \gamma\,\Phi^{-1}\!\left(1-\tfrac{1}{N e}\right)\right)
$$

`T` — число дней, `γ̂₃` — асимметрия, `γ̂₄` — эксцесс (нормальное = 3), `γ ≈ 0.5772`, `V[SR_n]` — дисперсия Sharpe по вариантам, `N` — число независимых вариантов. До M3 берём сырое N (консервативно); с M3 — `N_eff` = число кластеров вариантов по корреляции дневных доходностей, порог ρ = 0.5 (P-04; метод кластеризации — P-37). DSR по сырому N — в отчёт.

**PBO** (CSCV, Bailey и др., 2017): матрица дневных доходностей T × N режется на S = 16 блоков; для каждого из C(16, 8) разбиений IS/OOS берём лучший на IS вариант, считаем его относительный ранг ω на OOS и `λ = ln(ω / (1 − ω))`. `PBO = доля λ ≤ 0`.

### 4.4 Стабильность по годам `[предложено]`

- Матожидание > 0 (базовые издержки) в ≥ 2/3 календарных лет, где ≥ 20 сделок.
- Ни один год не даёт > 50% суммарной чистой прибыли.

### 4.5 Фильтры дня недели и времени `[предложено]`

Для каждого такого фильтра на OOS (WF-test + holdout):
1. Средний R в «разрешённых» корзинах выше, чем в «запрещённых».
2. Вариант с фильтром не хуже варианта без фильтра по `mean R × √(число сделок)`.
3. Оба варианта (с фильтром и без) — в счётчике вариантов.

Не проходит → фильтр снимаем, стратегию перепроверяем без него. Это главный вопрос идеи №1.

### 4.6 Не держится на одном инструменте `[предложено]`

Чистое матожидание > 0 на OOS минимум на **двух** инструментах того же класса (например NAS100 + US30 или SPX500). Исключение — только с ОК Nikita и объяснением механики.

## 5. S3 — проп-MC на OOS

| Метрика | Порог |
|---|---|
| EV на взнос | > 0 (определение — `EV₁`, [MONTE_CARLO §8](MONTE_CARLO.md#8-ev-на-взнос)) `[предложено: гейт по EV₁]` |
| P(1-я выплата) | ≥ 30% (стартовый порог) |

- Считается по каждой программе фирм, с оптимальным риском по фазам и **с предохранителями бота** (они не отключаются).
- Проходит, если хотя бы одна EA-доступная программа даёт оба порога. Рекомендация программы — из MC.
- В отчёте также: 5% нижняя граница P по внешнему бутстрэпу, стрессы ([MONTE_CARLO §6](MONTE_CARLO.md#6-стрессы)). Гейт — по точечной оценке.

## 6. Автоотказ

Отклоняем без MC, если по сделкам видно:

| Техника | Детектор по списку сделок |
|---|---|
| Мартингейл | риск сделки растёт после убытка (кроме округления лота); нужен риск сделки — у сделок движка (1R) детектор молчит (P-36) |
| Сетка | ≥ 3 открытых позиции одного направления по символу с ~равным шагом **против позиции**; пирамидинг в прибыль разрешён (P-36) |
| Усреднение против позиции | новый вход в ту же сторону, пока открытая позиция в минусе |
| Сделка без стопа | `sl` пуст хотя бы у одной сделки |
| HFT / Quick Strike | > 200 сделок в день; медианное удержание < 30 с; ≥ 20% прибыли — сделки короче 30 с (FN 2.6, P-36) |
| Тик-скальпинг | медианное удержание < 2 мин или медианный тейк < 3 × типичного спреда `[предложено]` |
| Латентный арбитраж, хедж между счетами, запрещённое фирмой | по семейству стратегии (список в карточке) |

## 10. Аудит [opus]

Обязателен перед S4 и S5. Дополнительно — автоматически, если:
- средний убыток > 3 × среднего профита;
- серия убытков в MC съедает > 50% общего лимита: 95-й перцентиль худшей серии подряд идущих убытков (в $ при оптимальном риске) > 50% общего лимита `[предложено: p95]`.

Аудит проверяет: доступ к будущему, издержки, соответствие правилам фирмы, логику выходов, разумность параметров, что сделки похожи на заявленную механику.
